# 轻量焚烧订单排期系统：生产加固与完整业务 MVP 设计

## 1. 背景与目标

当前仓库已经完成第一阶段的生产基础、认证和用户管理，但上线审计确认它仍缺少两类必要能力：

1. 现有基础设施尚有 CI 分支、请求体限制、就绪检查暴露、日志脱敏、数据库权限和维护任务等生产风险；
2. 物料、客户价格、订单、排期、焚烧任务和通知等完整业务闭环尚未实现。

本设计以 `master` 分支提交 `2598089b6820b9d5e1e3f24e88bce09b803d934c` 为基线，以原始需求文档和已经确认的 v4 交互原型为产品依据，在同一总体项目下按可独立验收的阶段交付生产加固和业务 MVP。

最终目标是：管理员能够维护客户、物料和专属价格，用户能够按可信价格提交订单，管理员能够确认、排期、编辑、取消和完成焚烧任务，双方能够查询历史与通知，并具备足以支持腾讯云正式部署、回滚和审计的工程基础。

## 2. 已确认决策

- 延续现有 Next.js、PostgreSQL、Prisma、数据库 Session 和模块化单体架构。
- 先完成生产加固，再按垂直业务切片交付，不一次性发布全部功能。
- 生产镜像发布到公开 GHCR。
- GitHub `master` 必须通过 Pull Request 和 CI 合并，不要求第二人审批。
- `Customer` 是独立业务实体，可选关联一个登录 `User`；专属价格归属于客户而不是登录账号。
- 未关联客户资料的普通用户不能下单，界面显示明确的管理员配置提示。
- 金额统一使用人民币“分”的整数保存和计算。
- 订单号按提交当天的上海业务日期生成，格式为 `yyyyMMdd-NNN`，生成后永不改变。
- 已确认但尚未焚烧的订单允许管理员编辑；用户在确认后始终只读。
- 已焚烧和已取消订单对双方均只读。
- 删除订单实际执行取消操作，必须保留原因、操作人、时间和完整历史。
- 定时维护由腾讯云 CVM 的系统定时任务每日调用应用维护 CLI。
- 审计日志在线保留两年后归档；订单、订单事件和取消历史永久保留。

## 3. 范围与分阶段交付

项目拆分为五个可独立测试、部署和验收的阶段：

1. **生产加固**：修复审计中的 CI、HTTP 安全、日志、权限分离和维护任务问题。
2. **客户、物料与价格**：建立客户资料、登录账号关联、物料库、别名、默认价格和客户专属价格。
3. **用户订单闭环**：实现可信定价、订单提交、待确认编辑、取消、查询和复制。
4. **管理员确认与排期**：实现待确认队列、确认、未来日程、管理员编辑、取消和 Excel 可粘贴复制。
5. **焚烧任务与通知**：实现每日任务、逾期、完成焚烧、汇总复制、站内通知和维护调度。

每个阶段必须包含数据库迁移、领域与接口测试、浏览器验收、文档和独立提交。腾讯云 PostgreSQL 的真实备份恢复演练不由代码替代，始终是最终上线门槛。

不在本轮范围内：在线支付、短信或微信推送、物流、库存、开放注册、多租户、复杂财务结算和用户自定义 HTML。

## 4. 总体架构与模块边界

系统继续使用单仓库、单 Next.js 部署单元和单 PostgreSQL 数据库。浏览器只能通过受保护的页面与 Route Handler 访问业务；任何前端显隐都不能替代服务器端权限。

建议领域模块如下：

```text
src/features/
  customers/       客户资料和登录账号关联
  materials/       物料、别名、启停
  pricing/         默认价格与客户专属价格解析
  orders/          订单、订单行、编号和状态转换
  scheduling/      已确认日程、每日任务与逾期查询
  notifications/   站内通知和幂等提醒

src/server/
  auth/ permissions/ audit/ db/ validation/
  http/             请求体、请求 ID、错误映射与安全日志
  maintenance/      定时清理、通知生成和归档
```

页面和 API 只负责输入输出适配；价格解析、状态转换、复制文本和汇总均由可独立测试的领域服务完成。所有跨表写操作必须通过领域服务在单一数据库事务中完成。

## 5. 数据模型

### 5.1 Customer

- `id`: UUID。
- `displayName`: 去除首尾空格后必填，规范化后唯一。
- `linkedUserId`: 可空且唯一；一个客户最多关联一个登录账号，一个账号最多关联一个客户。
- `version`: 乐观并发控制。
- `createdAt`、`updatedAt`: UTC。

管理员可以新增、搜索、重命名客户，以及关联或解除关联普通用户。重命名不改变客户 ID、专属价格或历史订单。客户本轮不物理删除。

### 5.2 Material 与 MaterialAlias

`Material` 包含 UUID、名称、默认单价分、单位、启用状态、排序、版本和时间戳。启用物料的规范化名称不能重复。

`MaterialAlias` 独立保存物料别名；别名录入时支持中英文逗号分隔、去空、去重。用户可以按名称或别名搜索启用物料。

界面中的“删除”是软删除。停用物料不会出现在用户下单列表中，但历史订单和专属价格继续保留；恢复时如与启用物料重名则返回冲突。

### 5.3 CustomerMaterialPrice

- 由 `customerId + materialId` 唯一确定。
- 价格以整数分保存，允许为零，不允许为负数。
- 删除专属价格后自动回退到物料默认价格。

用户查询物料时，服务端根据其关联客户解析有效价格；不能依赖或接受客户端提交的可信价格。

### 5.4 Order 与 OrderLine

`Order` 至少包含：UUID、永久订单号、客户、提交用户、联系人姓名、法事名称、申请焚烧日期、最终排期日期、状态、总金额分、版本、取消信息、焚烧完成时间和时间戳。

状态固定为：

- `PENDING_CONFIRMATION`：待确认；
- `SCHEDULED`：已确认、待焚烧；
- `BURNED`：已焚烧；
- `CANCELLED`：已取消。

`OrderLine` 保存物料 ID，以及物料名称、单位、单价分、数量和小计分的订单快照。物料或价格后续变更不得回写历史订单。

数量必须是正整数。用户端允许先输入数量再点击“添加”；输入为空时添加数量默认为 1，零、负数、小数或非数字必须被拒绝。

### 5.5 OrderEvent、Notification 与 OrderNumberSequence

`OrderEvent` 永久记录订单创建、用户编辑、管理员编辑、确认、取消和焚烧完成，包括操作者、前后状态、业务变化摘要和时间。

`Notification` 记录接收用户、类型、关联订单、内容、创建和已读时间；对每日提醒使用业务唯一键保证重复维护任务不会重复生成。

`OrderNumberSequence` 按 `Asia/Shanghai` 的提交日期维护序号。订单提交事务锁定或原子递增当天序列，生成 `yyyyMMdd-NNN`；修改排期日期不会修改订单号。

## 6. 定价、订单状态与事务规则

### 6.1 定价

有效单价按“客户专属价格优先，否则物料默认价格”解析。用户创建或编辑待确认订单时，服务器忽略客户端价格并重新读取当前有效价格，再写入订单行快照和总价。

管理员编辑 `PENDING_CONFIRMATION` 或 `SCHEDULED` 订单时，同样由服务端按照当前有效价格重新计算所修改的订单行。历史未修改订单不因价格库变化自动重算。

### 6.2 状态与权限

| 当前状态 | 普通用户 | 管理员 |
|---|---|---|
| `PENDING_CONFIRMATION` | 查看、编辑、取消 | 查看、编辑、确认、取消 |
| `SCHEDULED` | 只读、复制 | 查看、编辑、取消、标记已焚烧、复制 |
| `BURNED` | 只读、复制 | 只读、复制 |
| `CANCELLED` | 只读 | 只读 |

普通用户只能操作属于自己关联客户的订单。所有修改请求携带当前 `version`，版本不一致返回 `409` 并要求刷新。

取消必须填写非空原因，并保存取消人、取消时间和事件。系统不提供订单物理删除接口。

### 6.3 原子性

创建、编辑、确认、取消和完成焚烧必须在单个事务中同步写入订单、订单行、订单事件、通知和审计日志。事务内任一步骤失败则整体回滚，不允许出现已变更状态但缺失事件或通知的订单。

## 7. 页面与业务流程

### 7.1 用户端

- 查看启用物料及自己的有效价格，支持名称和别名搜索。
- 在搜索或推荐列表中先输入数量再添加，空数量默认为 1。
- 创建订单并获得永久订单号。
- 查询自己的订单，编辑或取消待确认订单。
- 确认后查看管理员最终排期和最新订单内容，但不能编辑。
- 查看站内通知和未读数量。

### 7.2 管理端

- 客户：新增、搜索、重命名、关联和解除关联登录用户。
- 物料库：新增、编辑、搜索、软删除、恢复、维护别名和默认价格。
- 专属价格：在物料入口中选择客户，新增、修改或删除该客户的专属价格。
- “待确认”页面直接复用首页“微信核对队列 / 待确认订单”的列表结构，左侧入口必须正确导航。
- 原“日程中心”统一更名为“已确认”，保留列表、日历、筛选和搜索能力。
- 支持待确认、今日、未来、逾期、已焚烧和已取消查询。
- 可编辑待确认订单并确认最终日期；可编辑已确认但未焚烧订单。
- 可取消未归档订单并保留历史；可标记订单已焚烧并保存实际完成时间。

### 7.3 查询与汇总

- 已确认查询包括 `SCHEDULED`、`BURNED` 和可查询的 `CANCELLED` 历史。
- 逾期指最终排期日期早于今天且状态仍为 `SCHEDULED`。
- 每日物料准备汇总只统计该日 `SCHEDULED` 订单。
- 每日任务总表统计选定日期的 `SCHEDULED` 和 `BURNED`，排除 `CANCELLED`。
- 每日总表必须包含姓名、法事名称、物料数量；已完成订单显示实际焚烧时间，未完成显示“待焚烧”。

### 7.4 Excel 可粘贴复制

每笔 `SCHEDULED` 或 `BURNED` 订单旁提供“复制 Excel”按钮，不生成文件。每种物料占一行，无表头，字段使用制表符分隔：

```text
yyyyMMdd\t法事名称\t物料名称\t数量
```

日期使用订单当前最终排期日期。例如：

```text
20260730\t祭祖送钱\t金元宝\t5
```

复制失败时显示完整可手动选择的文本。`CANCELLED` 订单不提供复制按钮。

## 8. API 与服务端校验

用户接口覆盖有效物料、订单创建/列表/详情/编辑/取消/复制文本，以及通知列表和已读。管理员接口覆盖客户关联、物料和别名、专属价格、订单筛选、待确认处理、已确认编辑、取消、完成焚烧、每日汇总和复制文本。

所有写接口按固定顺序执行：

1. 限制请求体大小；
2. 校验 `Origin`；
3. 验证 Session、强制改密状态、角色和账号状态；
4. 使用明确 Zod DTO 校验输入；
5. 校验订单归属和允许的状态转换；
6. 使用 `version` 执行乐观并发更新；
7. 在事务中写入业务数据、事件、通知和审计。

管理员密码重置也必须携带目标用户当前版本，避免覆盖并发修改。管理员编辑用户时，审计记录应保存必要且已脱敏的前后字段，而不是只记录版本号。

错误状态保持稳定：`401` 未登录、`403` 权限或账号状态不足、`404` 不存在、`409` 唯一约束或版本冲突、`413` 请求体过大、`422` 校验失败、`429` 限速、`500` 未知错误。生产 `500` 只向客户端返回通用信息和请求 ID。

## 9. 生产安全设计

### 9.1 请求体、请求 ID 与日志

- 业务 JSON 请求体统一限制为 32KB；同时验证 `Content-Length` 和实际读取字节数，以覆盖分块传输或缺失长度头的情况。
- 外部请求 ID 仅接受 UUID 或最长 64 字符的安全字符；其他值由服务器重新生成，避免突破审计字段长度。
- 未知异常记录请求 ID、方法、路径、错误名称和安全堆栈摘要，不记录正文或敏感值。
- 脱敏规则覆盖名称中含有 `password`、`token`、`cookie`、`authorization`、`secret`、`databaseUrl` 和 `connectionString` 的字段，包括临时密码、新旧密码、Session Token、Set-Cookie 和客户端密钥。

### 9.2 Cookie、HSTS 与 CSP

- 正式环境使用 `__Host-fenshi_session`，具备 `Secure`、`HttpOnly`、`SameSite=Lax` 和 `Path=/`；本地 HTTP 开发使用 `fenshi_session`。
- HTTPS 响应启用一年期 HSTS，不包含 `includeSubDomains`，避免影响未纳入部署范围的子域名。
- nonce CSP 属于低优先级后续任务。本轮保持现有 CSP，但不允许用户 HTML 和第三方脚本进入业务页面。

### 9.3 健康检查

- 公网仅暴露 `/api/health/live`，它不访问数据库。
- `/api/health/ready` 只允许 Docker 网络和服务器内部调用；公网代理对该路径返回 `404`。
- 容器健康检查使用内部就绪接口，外部存活监控使用公开存活接口，避免公网探测持续查询数据库。

### 9.4 数据库账号分离

- `MIGRATION_DATABASE_URL` 使用迁移账号，只在部署时执行 DDL 和 Prisma migration。
- `DATABASE_URL` 使用运行账号，只拥有应用业务表所需 DML 权限，并供 Web、管理员创建和维护 CLI 使用。
- 删除语义含混的运维数据库变量，部署文档给出腾讯云 PostgreSQL 建号、授权、默认权限和撤权步骤。

## 10. CI/CD 与供应链

GitHub Actions 同时监听针对 `master` 的 Pull Request 和 `master` 推送。仓库规则要求通过 PR 和必需检查后才能合并，不强制第二人审批，并在 GitHub 能力允许范围内禁止管理员绕过必需检查。

PR 流程执行：

- 安装锁定依赖、lint、类型检查；
- Prisma 校验和空库迁移；
- 单元、PostgreSQL 集成和 Playwright E2E；
- Next.js 生产构建；
- 生产依赖审计；
- Docker 构建和容器冒烟测试；
- Trivy 镜像扫描和 Syft SBOM 生成。

PR 不发布镜像。合并到 `master` 后，在相同检查通过的前提下把公开镜像推送到 GHCR，至少保留提交 SHA 标签；`latest` 只能作为便利标签，不能作为生产部署依据。发布流程使用 GitHub OIDC 生成签名和来源证明，生产环境固定部署镜像 digest。

## 11. 定时维护与数据保留

腾讯云 CVM 每日通过系统定时任务调用维护 CLI。CLI 必须可重复执行并输出结构化结果，失败时返回非零退出码。职责包括：

- 删除过期 Session 和失效登录预留记录；
- 删除超过 30 天且已解除阻止的限速记录；
- 幂等创建“今日到期”等订单通知；
- 将超过两年的审计日志先导出为加密归档，再从在线数据库清理；
- 保留所有订单、订单事件和取消历史。

部署文档必须给出定时任务、日志轮转、失败告警、手工重跑和归档恢复方式。维护 CLI 不拥有 DDL 权限。

## 12. 测试策略

### 12.1 自动化测试层次

- **单元测试**：定价、金额、订单编号、状态转换、权限、复制文本、脱敏和维护规则。
- **集成测试**：数据库事务、并发序号、版本冲突、软删除、专属价格、通知幂等和审计保留。
- **API 测试**：未登录、越权、非法状态、请求体超限、非法请求 ID 和重复提交。
- **E2E 测试**：用户下单、管理员确认、修改排期、取消、完成焚烧、复制 Excel 和通知。
- **浏览器验收**：桌面和手机尺寸各运行一次关键流程。

### 12.2 必测业务不变量

- 同一天并发提交不产生重复订单号，订单确认或改期后编号不变。
- 用户不能编辑已确认订单，管理员能编辑尚未焚烧的已确认订单。
- 已焚烧和已取消订单不可编辑，取消后历史完整且不计入任务。
- 客户专属价格优先；订单快照不因物料库后续改价变化。
- 未关联客户的账号不能下单。
- 一笔多物料订单复制为多行四列 TSV，可直接粘贴到 Excel。
- 请求体限制、错误日志和敏感字段脱敏在实际 Route Handler 中生效。

## 13. 数据库迁移、发布与回滚

所有结构变化使用已提交的 Prisma migration，生产禁止 `db push`。采用“先兼容、再启用、最后收紧约束”的扩展/收缩方式，避免新旧镜像短暂并存时不兼容。

发布顺序为：备份数据库、验证迁移与运行账号、使用迁移账号执行 `prisma migrate deploy`、按 digest 启动新容器、检查存活和内部就绪、完成登录与一条核心业务冒烟流程。

迁移失败时停止发布并保持旧容器运行。应用失败时回退至上一镜像 digest；存在不兼容数据变更时执行阶段对应的回滚脚本或备份恢复，不允许只回退容器而忽略数据库版本。

## 14. 上线验收门槛

只有同时满足以下条件才建议正式上线：

1. CI、镜像扫描、SBOM、签名和来源证明全部通过；
2. GitHub `master` 分支保护已实际生效；
3. 腾讯云 PostgreSQL 备份恢复演练成功，并记录恢复时间、数据完整性和操作人员；
4. 管理端与用户端关键 E2E 和移动端验收通过；
5. 越权、并发修改、请求体限制、错误日志和敏感信息脱敏测试通过；
6. 维护任务在测试环境重复执行并验证幂等；
7. 部署、回滚、数据库恢复、定时维护和日常运维文档齐全；
8. 不存在阻断级或高风险未处理问题。
