# 安全与可用性事件响应运行手册

## 启动条件与角色

登录异常、账号接管、敏感信息疑似泄漏、数据库不可用/误删、健康检查持续失败或未经授权的数据变更均启动本流程。事件指挥官负责决策和时间线；应用负责人负责账号/Session；数据库负责人负责备份、恢复和凭据；安全/合规负责人决定取证、监管和用户通知。

严重级别：S1 为正在发生的数据泄漏、全站不可用或不可逆数据损坏；S2 为局部功能中断或已控制的高风险账号事件；S3 为无现实影响的可疑信号。S1 立即通知全部负责人并停止发布，S2 在 30 分钟内响应，S3 进入当日排查队列。

## 前 15 分钟

1. 创建受控事件记录，写明发现时间、报告人、影响、当前版本/镜像 digest；指定指挥官。
2. 冻结非必要发布和迁移。不要删除容器、日志、数据库记录或备份。
3. 从外部和 CVM 内部分别检查 `/api/health/live`、`/api/health/ready`，记录 HTTP 状态、request ID 和时间。
4. 限制影响面：可在 Caddy/安全组临时阻断业务流量，但保留受控运维访问；不要开放数据库公网地址。

## 账号与 Session 处置

### 单个账号疑似被接管

1. 管理员在“用户管理”搜索手机号并确认用户 ID、状态和最近审计记录。
2. 将账号设为 `DISABLED`。此操作会拒绝新登录并撤销该用户现有 Session；验证旧会话访问 `/api/me` 返回 401。
3. 如确认可恢复使用，由管理员重置临时密码，使用独立渠道通知本人；用户登录后必须立即改密。不要在工单、日志或聊天中发送密码。
4. 保存相关审计记录的 request ID、时间范围和动作；不要导出 `passwordHash`、`tokenHash`、Cookie 或 Authorization。

### 全站 Session 撤销

仅当会话密钥/数据库泄漏或指挥官批准时执行。先确认可用备份并记录 Session 数量，再由数据库负责人在事务中删除 Session；这会让所有用户重新登录：

```sql
BEGIN;
SELECT count(*) AS sessions_before FROM "Session";
DELETE FROM "Session";
COMMIT;
```

执行后记录操作者、时间、受影响用户数和验证结果。若事务未提交，执行 `ROLLBACK`；不得随意删除用户或审计表。

## 数据库凭据轮换

1. 在腾讯云创建/更新最小权限应用账号凭据，保留旧凭据直到新连接验证完成；不要关闭 TLS。
2. 同时更新 `/etc/fenshi/app.env` 的 `DATABASE_URL`（容器 CA 路径）和 `OPERATIONS_DATABASE_URL`（宿主 CA 路径），以及只供 Prisma 使用的 `MIGRATION_DATABASE_URL`（迁移账号、宿主 CA 路径）；不在命令行回显，且两个角色凭据必须独立轮换。如 CA/VIP 变化，同时下载新 CA 并确认 `sslmode=verify-full`。
3. 运行 `MIGRATION_DATABASE_URL="$MIGRATION_DATABASE_URL" npx prisma migrate status` 和 `psql "$OPERATIONS_DATABASE_URL" -v ON_ERROR_STOP=1 -c 'SELECT 1'`，然后滚动重建 app 容器。
4. 验证 ready、管理员/普通用户登录后，撤销旧数据库凭据并再次确认旧凭据无法连接。
5. 如果怀疑数据库内容遭修改，禁止直接修补生产库；按[备份与恢复](backup-and-restore.md)克隆到隔离实例调查。

## 日志取证

1. 保存事件窗口前后至少 30 分钟的 Caddy、容器、腾讯云审计/数据库日志及镜像 digest，记录统一时区。
2. 应用日志为单行 JSON，使用 `timestamp`、`level`、`message`、`requestId` 关联请求。校验日志中没有密码、Hash、Token、Cookie、Authorization、数据库 URL 或完整请求体。
3. 对导出文件计算 SHA-256，写入只读证据清单；原件设为只读，只在副本上分析，并记录每次访问者和时间。
4. 不在普通工单粘贴原始日志；只附受控存储链接和脱敏摘要。

## 恢复、通知与结束

1. 采用最小变更恢复：回滚到上一镜像按[部署手册](deploy-tencent-cloud.md#5-回滚到上一镜像)执行；数据恢复只允许克隆到新隔离实例并校验后切换。
2. 恢复流量前必须同时满足 live/ready 200、迁移状态正常、管理员和普通用户登录成功、相关账号/旧 Session/旧凭据已失效。
3. 安全/合规负责人根据是否存在个人信息或凭据暴露、受影响人数/地区、证据可信度和法定时限，书面决定是否通知监管方和用户。对外内容应说明影响、时间范围、已采取措施和用户动作，不披露攻击细节或其他用户数据。
4. 事件结束后 48 小时内完成时间线、根因、影响范围、RPO/RTO、证据链接、改进项、负责人和截止日期；确认临时安全组规则已撤销，但证据和备份按策略保留。
